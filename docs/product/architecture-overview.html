01

入口：把请求送到正确负责人

CLI 是命令分发器；Interface 是 Dashboard、宿主适配器与诊断的人机边界。两者是并列入口，不是谁包着谁。

CLI（命令入口）把用户命令送到对应流程输入：命令与参数　输出：运行时调用
Interface（人机与宿主边界）承接 Dashboard、宿主适配器与诊断输入：人或宿主请求　输出：安全交互
请求进入受控任务循环
02

闭环：做事的人不能自己宣布完成

Orchestration 管顺序与返工，AI 给策略和语境；两者只能通过统一能力网关调用 Worker、Verifier、Review 与 Checkpoint。

Orchestration（流程编排）管顺序、重试、事务和完成门输入：计划与任务状态　输出：下一步动作
AI（策略与语境）做路由、注入、Skill 匹配和异步审查输入：请求与清洗上下文　输出：决策建议
Capabilities（原子能力）统一执行 Worker、Verifier、Review 与 Checkpoint输入：能力名与上下文　输出：结果与证据
状态、副作用与验收证据统一落地
03

底座：让每次执行都能恢复、核对、追责

文件、锁、Git、命令、配置和 hash 链账本都集中在最低层；上层不各写一套基础设施。

Infra（可信基础设施）负责原子落盘、锁、Git 协调、命令安全与证据账本输入：文件、命令与运行时数据　输出：可恢复状态与可信证据

线性完成任务

目标不是“Worker 说做完了”，而是独立验证、质量门和验收证明全部通过后才 Checkpoint。

1. 接收任务CLI 接收 plan / run 命令
2. 推进计划挑出下一项，管理状态与重试
3. Worker 执行只产出 DoneClaim，不自证完成
4. 独立过门Verifier → Scope → Review → Proof
5. 证据入账Checkpoint 与 ledger 落盘

并行成果合入

子 Agent 在隔离目录工作；成果必须经过 admission 事务与同一套质量门，成功提交或成功回滚后才释放所有权。

1. 发起并行运行CLI 接收 parallel run
2. 创建隔离执行为子 Agent 分配独立结果目录
3. 产出候选成果Worker 只能提交待验收结果
4. Admission 合入锁定基线，过门，提交或回滚
5. 留下可恢复记录Git、ownership 与 ledger 对账

跨设备接力

设备之间交接的不是一句“你继续”，而是远端已 push 的 commit、明确 owner 和绑定的集成基线 SHA。

1. 准备交接CLI 接收 claim / handoff 命令
2. 绑定任务所有权记录设备、任务和预期接收方
3. 普通 Push 交接Git 协调保存 commit 与基线
4. 接收方重新校验检查 owner、SHA、候选树和质量门
5. 集成并对账Push 集成 commit 后才 Checkpoint
