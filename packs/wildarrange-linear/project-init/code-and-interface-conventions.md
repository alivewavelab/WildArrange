## 通用代码规则

- 同一业务概念只使用一个术语；名称表达业务含义。
- 优先提前返回，避免不必要的深层嵌套和互斥布尔状态。
- 禁止空 `catch`、静默吞错或丢失原始错误原因。
- 异步任务必须被等待、返回或由明确生命周期接管。
- 网络、数据库、文件和进程等副作用放在明确边界层。
- 只有存在真实替换、隔离或测试需求时才增加抽象层。

## 接口规则

接口包括 HTTP、RPC、事件、消息队列、IPC、CLI、配置文件，以及跨模块公共类型和函数。

- 每个接口只有一个权威 Schema 或类型契约；本文件不登记具体接口清单。
- 输入明确必填、可选、可空、默认值和未知字段处理。
- 错误使用稳定错误码；展示消息不得充当错误码。
- 同一业务字段的名称、类型、单位和可空性保持一致。
- 可能被重试的写操作定义幂等行为；公共接口不得直接破坏兼容性。

## 生产与测试边界

测试文件存在于仓库不等于污染。判断污染只看测试设施是否进入生产运行路径、生产依赖图、生产行为或生产产物。

- 禁止测试专用业务分支、Mock/Fake/Stub、测试端点、测试依赖、夹具、样例密钥或调试后门进入生产路径或产物。
- 禁止通过隐藏开关在生产入口启用认证、权限、支付或业务校验绕过。
- 开发模拟器和本地 Mock 使用独立入口或构建目标；生产代码不得反向依赖测试模块。
