明确不融合项

不建第二套完成状态机

Registry 的 reviewRequired 不能变成 task 状态、审批队列或 checkpoint 前新门。现有 pipeline 已承担完成裁决。

生活化解释：资产台账不能变成第二位厂长。

不重复登记每个测试

WildArrange 的 tooling/run-tests.mjs 已逐文件执行 test/*.test.mjs；Registry 只按真实 Suite/Runner 归组。

生活化解释：登记“整支车队”，不要把每颗螺丝单独建档。

不自动接 Hook / CI / build

不在每次工具调用触发全仓库存，也不让 inventory 失败阻断产品运行；是否成为 CI 门需单独批准。

生活化解释：盘仓库不该让每位顾客进门都停业清点。

不复制 Gamecopilot 身份

不复制 commit、asset ID、Owner、路径、26/24/2 数量与 blockingAt。

生活化解释：不能把隔壁公司的资产编号贴到自己仓库。

最短融合方案（需另行批准后才实施）

  1. 先只读建清单：只识别 WildArrange 真实的两类工程入口（当前至少 npm test、check:arch）、现有 test suite runner，以及产品运行链中的 runtime protections；不写 Registry。
  2. 先落最小 Registry：只登记“真实 Runner 的 Suite”和“确有独立故障后果的 Gate”；把 verifier/scope/review/acceptance-proof/checkpoint 视为现有交付链组件，不拆成五套新的治理审批。
  3. 提炼盘点器：复用通用函数，去掉 Gamecopilot 分组和 pnpm 假设；只生成一个 WildArrange 自有 inventory HTML，check 模式只读。
  4. 最后才加可选 Skill：仅结构变化时显式调用；中立 Review 输出建议，不改变 task 状态。先跑定向合同测试，再按项目要求跑 npm test 与 npm run check:arch。

生活化解释：先数清家里真正有什么，再做一本薄账；不要先搬来整套仓库管理制度。

主要风险与停止线

风险真实后果停止线
Bootstrap 污染把当前 WIP 或后来发现的资产冒充为历史资产，绕过新增审查。没有干净、人工确认的冻结 commit 就不创建 bootstrap。
重复门禁开发者同时维护 task gate 与 Registry gate，出现两套“是否完成”的答案。Registry 永远只描述结构；completed 只由现有 delivery pipeline 决定。
扫描绿灯错觉“0 未登记”被误读成测试通过、Runtime 正确或全仓无漏门。CLI/HTML 同屏声明配置覆盖、Runtime Gate 人工边界和未运行测试。
发现面膨胀为 Cargo/CI/Python 等当前不存在的技术栈预付配置和维护成本。发现规则只来自当前真实文件与命令，出现新技术栈后再加。
产品包膨胀tooling、Skill 或生成 HTML被意外发布给终端用户。实施时明确 package files 是否包含；当前 package.json 仅包含 arch tooling（37）。

最终裁决

推荐融合边界：吸收“验证资产结构可见性”这一能力，不吸收“另一套交付治理”。最小值得保留的是：三类资产语义、真实 Runner 对齐、Baseline/Branch/WIP 观察、HTML 新鲜度、结构变化的只读中立 Review；其余 Gamecopilot 配置、历史、任务和快照全部排除。

当前不授权实现：本报告是候选方案，不代表已批准新增 tooling、Skill、Registry、package scripts、测试或 AGENTS 路由。

生活化解释：可以买“盘点方法”，不要连隔壁公司的仓库、编号和审批链一起搬来。
