WildArrange 与 GameYo 工作流对照图

结论：两者共用同一套治理底座。区别在于 GameYo 在进入编码前，多了游戏生产语义层：策划、资产规格、美术验收、试玩验收。主编排者仍由 WildArrange 掌握；GameYo 自定义的是阶段 worker 和阶段 loop。

共用治理能力 GameYo 新增游戏生产阶段 Gate / 验收裁决 返工 / 变更请求

总图

WildArrange 通用治理 workflow

用户目标 / 任务输入输入需求，进入本地文件协议。
↓
ProducerAgent 编排拆任务、定边界、生成 plan、绑定 writable_paths 与 verify_commands。
↓
Task / Worker 执行worker 产出改动和 DoneClaim，但不能自证完成。
↓
Verifier / Scope / Review执行验证命令、检查改动范围、复核质量风险。
↓
Acceptance Proofworker、verifier、scope、review、success criteria 全部满足才可 checkpoint。
↓
Checkpoint / Ledger / Resume任务完成、证据入账、后续可恢复。
↺
失败返工gate 失败回到 pending，按失败原因返给对应 worker。

GameYo 游戏生产 workflow

用户目标 / 游戏需求例如新增玩法、角色技能、UI 表现、关卡机制。
↓
ProducerAgent 编排仍由 WildArrange 掌握：判断任务类型、选择阶段 loop、控制 gate 与 ledger。
↓
策划 Loop / GameDesignerAgent产出玩家目标、核心循环、规则、数值、边界情况、验收场景。
↓
Design Gate检查策划产物是否足以指导后续资产与实现。
↓
美术资产 Loop / ArtDirectorAgent产出资产清单、尺寸、格式、状态、命名、导入路径、视觉约束。
↓
Asset / Visual Gate检查资产规格完整性和视觉一致性，不让编码阶段猜素材。
↓
编码 Loop / GameplayCoderAgent进入通用实现流程：改代码、跑 typecheck/test、提交证据。
↓
Verifier / Scope / Review复用 WildArrange 的代码 gate。
↓
试玩 Loop / QAAgent跑验收场景、可玩性检查、回归风险、release verdict。
↓
Final Acceptance Proof设计、资产、代码、试玩证据齐备后才完成。
↺
返工 / ChangeRequest需求不清回策划；视觉问题回美术；实现失败回编码；体验问题回策划或 QA。

GameYo 需要补的最小扩展口

Agent Pack

.wildarrange/agent-packs/gameyo/manifest.json声明 GameYo 有哪些阶段、哪些 worker、每个 worker 的权限和产物契约。
↓
agents/*.md策划、美术、编码、QA 的阶段提示词。提示词只描述工作职责，不允许绕过 gate。

Stage Loop

stages/*.json声明每个阶段的输入、required_outputs、下一阶段、gate 绑定。
↓
统一 GateAgent 可替换，loop 可扩展，但最终裁决仍由 WildArrange runtime 掌握。

核心判断

GameYo 新增的是游戏生产语义，不是新的治理主权。 ProducerAgent 负责调度；策划、美术、编码、QA 是阶段 worker；Gate 负责判定；Ledger 负责记账。这样既保留 WildArrange 的强治理底座，又能适配游戏开发中“先策划、再资产、再实现、再试玩”的真实生产节奏。
