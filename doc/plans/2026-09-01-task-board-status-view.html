工单总账改为“按进度看任务”的状态看板

把现在从上往下翻的工单列表，改成从左到右推进的工作台。用户先看到每项工作在哪个阶段；技术状态、门禁证据和历史记录点开卡片后再看。

本页只确认交互与状态映射，不实现 Dashboard
核心判断：看板列只表达“任务走到哪一步”。

“新功能 / Bug / 验收纠错 / 维护”是任务类型，显示为卡片标签；P0 / P1 / P2 是优先级，用卡片左侧色条表示。它们都不是流程阶段，不能各占一列。

输入 → 处理 → 输出

输入：现有真实数据 工单状态、任务类型、优先级、负责人、依赖、门禁证据、待人工处理事项
→
处理：只做展示映射 把 8 个内部任务状态归入 6 个用户阶段；保留原始状态，不修改运行时状态机
→
输出：工单状态看板 六列看进度；卡片看关键信息；底部抽屉看完整描述、历史、证据和下一步操作

每张卡片先展示什么

第一眼：这是什么标题、工单编号、任务类型、所属 Plan。
第二眼：有多急、谁在做P0/P1/P2 色条、负责人、等待的前置任务。
第三眼：下一步是什么每张卡只有一个主要按钮，按钮文字随阶段变化。

点击卡片后再从底部抽屉查看：完整需求、允许修改范围、验证命令、门禁证据、失败历史、状态变化历史。总账首页不直接铺开这些技术细节。

不能混成同一维度的内容

  • 任务类型不是阶段：feature、bug、acceptance_correction、maintenance 只做卡片标签和筛选条件。
  • 优先级不是阶段：P0 紧急P1 正常P2 稍后只改变排序和色条。
  • 门禁结果不是任务状态：测试、范围、复核、验收证明显示在“验收中”卡片的进度条，不再额外造五列。
  • 计划审批是 Plan 状态：显示在看板顶部的全局提示，不把全部任务复制进“等待计划批准”列。
  • 隔离成果待接纳是子 Agent 运行状态：在对应任务卡上显示“待人工接纳”徽标，仍以任务真实状态决定所在列。
  • 越界审批是待处理事项：绑定到任务卡并突出下一步，不篡改任务原始状态；无对应任务时放在看板顶部的待处理提醒。

交互边界

  • 第一版不允许任意拖动卡片。状态由真实工作流推进，避免用户把未验证代码直接拖到“已完成”。
  • 筛选保留但收进一行。可按 Plan、任务类型、优先级、负责人筛选；搜索编号和标题。
  • 列内排序固定。P0 在前，其次 P1、P2；同优先级按最近更新时间倒序。等待依赖的任务不抢到可执行任务前面。
  • “需要处理”必须可行动。不能只写“失败”；要同时给出原因、证据摘要和唯一下一步。
  • 列表不删除，只降级为备用视图。需要批量搜索、审计和导出时切换“表格视图”；默认入口是状态看板。

本方案不改什么

不新增任务状态，不改变任务总账文件，不改变开发与验收流程，不把看板拖拽当作状态机。实现阶段只需要在 Dashboard 读取现有工单数据后增加一层展示映射，并复用现有任务操作。

当前实现依据：src/infra/runtime-store.mjs 的 8 个任务状态；src/orchestration/plan-state.mjs 的任务类型、优先级、依赖和验收字段；src/interface/dashboard.mjs 的工单总账、任务操作、状态标签与门禁展示；src/orchestration/status.mjs 的任务总账与待处理投影。
