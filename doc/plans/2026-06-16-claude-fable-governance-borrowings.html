Claude Fable 5 Prompt 对 WildArrange 的治理借鉴

结论：不要照搬提示词文本。应借鉴它的“行为决策表”思想，把现在偏代码验收的 WildArrange 扩展成“请求分流、工具选择、证据查验、产物交付、用户授权”都可审计的本地治理框架。

最短可落地路径

输入用户请求、项目规则、已安装工具、当前任务状态
→
处理组件RoutePolicy 先判定查证/技能/连接器/文件产物策略
→
输出计划任务、必读 Skill、必跑验证、授权动作、交付物清单

优先级建议

P0

把“工具选择”升级为可审计 RoutePolicy

Claude 提示词把“内部工具优先、外部连接器先搜索、第三方 App 需用户选择、浏览器兜底”写成明确决策表。WildArrange 已有 routes 和 semantic shadow，但还缺少工具/连接器授权层。

项目证据：routes.json 已能按 intent/domain 选 agent、skill、risk；架构文档要求确定性路由保留证据。提示词证据：mcp_app_suggestions 和 connector 工具描述把搜索、建议、直接调用的边界写清。

P0

把 Skill 从“推荐加载”变成“任务前置证据”

Claude 的强点是先读相关 SKILL.md 再动手。WildArrange 目前能匹配 skill，但 review gate 只看到项目规则是否注入，不能证明 worker 真按相关 skill 做了准备。

建议新增 requiredSkills / skillReadEvidence：plan 导入时生成，execute 前确认，acceptance proof 检查。

P1

增加“时效性查证门”

Claude 把当前信息、陌生实体、政策价格职位等设为必须搜索。WildArrange 可抽象成 volatility gate：任务涉及外部依赖、产品版本、政策、价格、新闻时，要求 evidence 引用官方文档或搜索结果。

项目已有 research intent 和 route evidence，可扩展为 verify_commands 之外的 knowledge evidence。

P1

建立交付物生命周期

Claude 明确区分上传文件、工作区、最终输出。WildArrange 已有 .wildarrange 运行态和 checkpoint，但缺少 final artifacts manifest，用户验收时不一定知道“该看哪个文件”。

建议在 checkpoint 写入 deliverables.json：artifact path、type、viewer hint、verification summary、human acceptance status。

P1

把版权/商业边界做成发布前 gate

Claude 的版权规则是硬门槛。WildArrange 已有商业边界文字，但可在 npm pack / publish 前加入 prompt-pack provenance 检查，避免把外部提示词、受限源码或近似改写带入包。

项目已有 commercialBoundary 和 pre-publish 命令约束，下一步是自动扫描证据化。

P2

把语气/输出格式变成 adapter 规则，而非 core 规则

Claude 提示词中大量语气和格式规则适合消费端体验，但不应污染 WildArrange core。可放到 Codex/Cursor adapter 或 prompt variants，保留 core 的本地文件协议纯度。

项目架构已经要求 core 产品中立，prompt variants 是配置化 appendix。
