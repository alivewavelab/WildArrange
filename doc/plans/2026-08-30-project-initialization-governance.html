WildArrange 项目初始化治理融合方案

状态：待实现方案。目标是在不建立第二套任务系统的前提下，把项目专属规范、测试授权边界和任务治理入口加入 WildArrange 初始化流程。

关键决策

WildArrange 的 .wildarrange/team/tasks.json、Dashboard 与 ledger 已覆盖任务可视化、状态和历史。它们继续作为唯一任务真源；不接入 ClickUp，也不在 Markdown 重复维护任务表。

输入 → 处理 → 输出

现有项目与已有规范
→
只读探测目标文件
→
仅创建缺失模板
→
返回待人确认项

命令与边界

显式启用wildarrange init --project-docs
  • 普通 wildarrange init 保持现状。
  • 只有显式参数才创建项目文档。
  • --architecture 按需创建架构说明。
永不覆盖已有项目安全补建
  • 存在的文件只报告 preserved。
  • 不合并、不重写、不推断现有规则。
  • 输出待人工补链接和确认事项。
必需文档最小初始化集合
  • AGENTS.md
  • doc/standards/code-and-interface-conventions.md
  • doc/testing-and-acceptance.md
  • doc/progress.md（治理入口，不复制任务）
按需文档doc/architecture.md
  • 只有系统边界已经明确时创建。
  • 不为了凑齐文档编造架构。

测试授权边界

  • 初始化时由人类确认测试策略和强度。
  • AI 默认只补与改动复杂度匹配的基础单元测试和必要回归测试。
  • 未经确认，不得扩张对抗、Fuzz、属性、组合矩阵、soak、额外 E2E、Golden、快照、哈希门禁或新测试框架。
  • 高风险行为只允许提出成本收益方案，获得人类确认后实施。
  • 测试设施不得进入生产路径、依赖、行为或产物。
  • Review 按业务保护价值和人类批准范围判断，不以测试数量代替结论。

验收

一致性
