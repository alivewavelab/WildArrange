一、统一执行链（原图已对，保留）

Workflow→ Execution Controller→ Capability Gateway→ Capability→ Results / Events / Receipts

这条主干是整张图最稳的骨架，重构不动它，只把横切关注点从主干里抽出去。

二、四条解耦切缝（重构下刀的位置）

A. 计划 ↔ 执行

缝左：AI Workflow Engine（出 Plan/CapabilityCall）
缝右：Business Workflow Engine + Execution Controller

契约：Plan 是纯数据；AI 引擎无状态、不直接调能力。

B. 编排 ↔ 能力（枢纽）

缝左：Execution Controller → Capability Gateway
缝右：原子能力（Layer 5）

契约：I/O schema + progress/error + 副作用分级 + undo/rollback。

C. 能力 ↔ 宿主资源

缝左：原子能力
缝右：游戏进程 / 文件系统 / OS（Layer 7）

契约：资源句柄由支撑层独占，能力只借不抢。

D. 云端 ↔ 本地

缝左：云端目录 / 计费 / 聚合 trace
缝右：本地 live state / run ledger / artifacts

契约：context 合并 + 可重放性标志。

三、六个耦合气味（重构重点盯这里）

1. Layer 3 三头耦合

Business Workflow Engine（状态机）、AI Workflow Engine（计划）、Execution Controller（生命周期/路由/超时/重试）都碰 workflow 状态，没说谁拥有唯一真相源。

→ 指定 Business Workflow Engine 独占状态，另两个只读写它。

2. Business Control Slots 回灌方向未定

扩展点既能注入上下文又能回写编排 = 隐式回调，重入与循环依赖从这里冒出。

→ 二选一：只读注入，或产出结构化结果走契约回灌。

3. Effect-Undo 一刀切漏掉不可逆动作

Game Vision 纯读；Runtime Modification 可 undo；但 Input Automation / 游戏内动作不可撤销（已发生在游戏世界）。

→ 契约分 read / write-undoable / irreversible 三类，irreversible 强制 checkpoint + 确认。

4. 三个能力抢同一游戏进程

Game Capability、Input Automation、Runtime Modification 各自 hook 同一进程，却标成"独立原子能力"，靠游戏状态隐式耦合。

→ 引入 Game Session 资源管理器，能力借句柄。

5. Trace/Replay/Checkpoint 三套机制

云端 Operation Trace（L2）、本地 Run Ledger（L6）、Checkpoint Manager（L7）若非"一 schema 三 sink"会漂移；重放只对确定性能力成立。

→ 统一事件 schema + 能力级 replayable 标志。

6. 计费/权益横切主干

写进 Execution Controller 把"钱"耦合进编排；塞进 Gateway 每个能力都付间接成本。

→ 做成 Execution Controller 的可插拔策略槽，主干业务无关。

四、副作用分级契约（B 缝的核心，P0）

类别代表能力契约要求处理
read（纯读）Game Vision / Performance Telemetry无副作用无需 undo，可重放
write-undoableRuntime Modification / MOD Capability副作用 + undo执行前 checkpoint，失败回滚
irreversibleInput Automation / 游戏内动作副作用，无 undo强制 checkpoint + 用户确认

五、重构优先级

P0

冻结能力契约（B 缝）

I/O + 副作用分级 + undo。锁住它，Layer 5 内部随便改。

P0

AI Workflow Engine 无状态化

状态挤回 Business Workflow Engine，AI 引擎变纯函数，可换/可测/可重放。

P1

Game Session 资源管理器（C 缝）

能力不再各自 hook 游戏进程。

P1

统一事件 schema

trace/replay/checkpoint 一个 writer、三个 sink。

P2

权益/计费外提成策略槽

主干去业务化。

P2

明确 Slots 回灌方向

只读注入 or 走契约回灌，二选一。
