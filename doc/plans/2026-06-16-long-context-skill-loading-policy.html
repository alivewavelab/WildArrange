长上下文与 Skill 加载策略

结论：6000 字符一刀切不合理。WildArrange 应改成“目录常驻、Skill 激活后完整加载、重型参考按需加载、提示词规则短而硬、所有截断显式可见”的治理模式。

处理流程

输入用户请求、hook 事件、可用 skill 目录、项目规则、任务状态
→
处理组件ContextBudgetPolicy 判断目录、规则、Skill、参考材料分别用哪种加载级别
→
输出上下文包、加载证据、截断/溢出告警、后续按需读取入口

建议预算

内容类型默认策略建议上限超过时
Skill 目录 启动/PromptSubmit 常驻，只放 name、description、path 约 2% 上下文窗口；未知窗口用 8,000 字符 优先缩短 description，再省略低优先级 skill，并显式告警
已激活 Skill 的 SKILL.md 激活后完整加载，不静默截断 软建议 500 行 / 5,000 tokens；硬上限可设 40k-80k 字符 若超硬上限，要求分段声明或转 references，不允许假装已完整加载
重型工作流 / references 不随 Skill 主体加载，按触发条件读取 单文件 20k-50k 字符可接受，但必须有目录和触发说明 按 section/range 读取，写入 loadedSections 证据
系统/Agent 提示词 短、硬、稳定，只保留不可违反规则和路由哲学 建议 4k-12k tokens 内，越短越好 拆成 hook capsule，不把大段案例和参考资料放常驻提示词
项目规则 AGENTS/CLAUDE 启动时加载指令链；路径越近优先级越高 参考 Codex 默认 32 KiB，可配置到 64 KiB 保留后加载覆盖关系；截断必须显示来源和缺失量

落地改造

P0 取消静默 6000 字符截断

附件加载结果必须带 truncated、chars、omittedChars、policy。治理依据不能用静默摘要。

P0 引入 SkillCatalog 与 SkillActivation

hook 默认只注入目录；任务命中后用专门激活入口加载完整 SKILL.md，并列出 scripts/references/assets，不急着读取。

P1 支持 Section 化加载

长 skill 可在 frontmatter 或目录索引中声明 sections、required、onDemand。hook 按事件加载必需 section，references 按条件读。

P1 保护已激活 Skill

PostCompact 不能把已激活 skill 压没。压缩时保留 skill id、hash、loadedSections 和关键规则，必要时重新激活。

P1 增加预算诊断命令

wildarrange context budget 输出当前 hook 将加载什么、多少 token/字符、哪些被省略，方便调试和审计。

P2 用测试找真实阈值

不要迷信固定数字。用典型任务跑 6k、12k、24k、48k 的 skill 版本，对比完成率、遗漏率、成本和延迟。

治理原则

提示词是宪法，必须短而稳定；Skill 是作业指导书，可以更长但必须按需激活；references 是档案库，可以很大但不能预加载；hook 是交通灯，只在正确时机给正确信号。
