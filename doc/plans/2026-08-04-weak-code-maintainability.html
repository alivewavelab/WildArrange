弱代码可维护性方案 v5（定稿）

2026-08-04 · 四模型代码审查 → RuntimeSafetySDK 概念对照 → Opus/GLM 双方案评审 → 裁决定稿

前提：开发者本人不读代码。维护操作者是 AI，人做三件事：描述症状、看红绿灯、审判框架的每条决策。 可维护性 = AI 改一处能向人机器化证明「没碰别的模块、没破坏既有行为」； 框架可信 = 每次拦截/放行都留痕、可读、可标注、可被复审。
双评审发现的两条顺序性铁律（违反则整个方案失效）：
1. 先武装门，再透明化——默认配置下 review 门是同义反复、qualityGates 全关。若先做决策面板，人会对着一条稳定的绿灯流标「对了」，调参数据源从第一天就是垃圾。配置地板必须与决策记录同期或更早。
2. 决策记录不进 hash 链 ledger——ledger 追加是 O(全文件) 且持全局锁，106 个发射点字段异构。决策记录走独立 .wildarrange/decisions.jsonl（可丢、可截断、可重建），只在四个干净缝隙发射；历史 ledger 不回溯、不做读侧归一化。

块一（底线）：AI 定位 + 隔离修复闭环

人描述症状 → AI 按错误内联的 {code, module, next_action} 定位到单区单文件 → AI 在目录契约内修改 → wildarrange impact 列出波及文件与应跑测试 → 分区测试 + 边界测试 + npm test 全绿 → 人看到一句话：「影响 3 个文件，47 个测试全过」。
项内容归属分区优先级
五区边界测试已有，AI 无法跨区耦合而不变红。补：bin/ 纳入扫描（CLI 是产品主入口，目前在边界外）testP0
目录级 AGENTS.md已有，AI 的修改契约，保持健康即可各目录已有
wildarrange impact不重写扫描器：把 dependency-boundary.test.mjs 里已被对抗加固的 buildDependencyEdges/maskSource 提取到 infra，命令与边界测试共用；扫描器自身的对抗测试为不可削弱底线infra + bin 薄壳P0
统一错误协议（收窄版）不做全仓 refactor。只覆盖三处：gateway 信封、delivery-pipeline 返回、CLI 非零退出。错误内联 {code, module, next_action}（AI 只读错误消息，不会去翻文档）；契约表进 doc/contracts 仅作人用参考capabilities + orchestration + binP0
分区测试入口wildarrange test --zone，依赖 impact 的应跑测试清单；wildarrange-core.test.mjs 已 158KB，秒级反馈是闭环前提bin + testP0
诊断/门控分离真实缺陷很具体：runDoctor 7 个 check 顺序 await 无 try/catch，一个崩全崩；且 doctor 会写 hash 链 ledger（抢门控同一把锁）。修法：7 个独立 try/catch + 分项 status + doctor 不再写 ledgerinterfaceP0
配置地板 + 门未武装灯verify 非空非 trivial、review 至少一条非同义反复 lane、qualityGates 至少一项 required；不满足时 wildarrange status 顶部常驻黄灯「门未武装」，不显示绿。trivial verify 从 doctor warn 升级为 acceptance-proof failinfra + capabilitiesP0（自 P1 提升）
复现测试先行写进 AGENTS.md 作为维护纪律。承认这是纪律不是机制，不放进 verifier 强制（机制化留待后续评估）docP2 纪律

块二（信任基石）：决策透明与调参回路

项内容归属分区优先级
决策记录发射独立 .wildarrange/decisions.jsonl，只在四个缝发射：delivery-pipeline（五门）、ai/hooks（已有 decision 字段）、admission、routing。结构 {ts, gate, decision, code, reason, 输入摘要, evidence_path, taskId, runId}。可丢可截断可重建，不进 hash 链orchestration + ai 发射，infra 存储P0
wildarrange decisions CLI 投影只读派生，不二次写入；每条三行：发生了什么 → 命中哪条规则 → 证据在哪。必须处理半写 jsonl（跳过坏行并提示）。Dashboard 面板延后到第三阶段interfaceP0
Cursor hooks.json 硬拦截从脚注升为第一阶段首项。官方文档已确认 preToolUse(Write/Delete/Shell) 可事前 deny、failClosed 可配、exit 2 兼容。任务 = 渲染 .cursor/hooks.json + 输出协议映射 + 冒烟测试。没有它，块二验收第一条在开发者实际环境里永远达不成interfaceP0 首项
标注回写（带硬约束）① 只有拦截和非确定性放行（LLM review、路由 shadow、admission 归属）进标注队列，确定性 PASS 只进流水——否则队列 99% 是无信息绿灯；② 标注强制分类（规则错/个案错/误标），理由可选；③ 统计以「规则 × 标注」为单位，单条标注不绑架整条规则；④ 标注永远不能自动改门——新增测试钉死：标注数据任何路径不得写 config / verify_commands / gate 开关interface + infraP1
verbose 汇报分级初期默认 verbose = 每次 run 结束一次门决策汇总（不是实时逐条 tail）；随信任建立可降 normal/quietorchestrationP1
异步审查（拆分）确定性统计（门触发计数、从未触发的门、规则同期触发）用代码实现，可重跑可复核；「可疑放行」类判断才用 LLM，且必须复用 archivist-router 既有不变量：deterministic 证据保留、只作第二意见、无 key fallback、结论进报告不进完成链、绑定 decisionId。冷启动 6-8 周只出计数不出率。
防自查原则（开发者裁决）：凡不需要完整聊天上下文的审查，一律走外部 LLM 调用而非当前会话自查——① 上下文隔离是底线：审查者必须是全新上下文，只读清洗后的决策投影 + 证据指针，绝不摄入执行 Agent 的会话/推理过程（同模型不同会话即可消除大部分自查偏袒）；② 模型家族不同是加分：审查通道独立配置 provider/model（复用 llm-provider，OpenAI-compatible），默认建议与工作模型不同家族，消除同模型的系统性盲区；③ 类比 Codex：主 Agent 做计划、编码强制派给子 Agent——即使同为 GPT，职责与上下文分离本身就构成独立复核		ai（统计可放 infra/interface）P2
周期健康摘要扩 doctor 实现（修+扩比新建 Agent 便宜自洽），初期只出计数interfaceP2
