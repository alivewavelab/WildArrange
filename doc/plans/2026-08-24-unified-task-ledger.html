目标流程

1. 收到工作

新功能、Bug、用户验收打回。

输入：用户请求 / 验收意见 / 错误证据
输出：待登记请求
→

2. 自动建 Task

先生成可追踪编号和 draft，信息不足也能先留底。

输入：请求原文与来源
输出：Task draft
→

3. 补齐并就绪

生成范围、成功判据、验证命令和优先级，draft 才能变 pending。

输入：Task draft
输出：可执行 Task
→

4. 跑现有 Loop

worker → verifier → scope → review → proof → checkpoint。

输入：可执行 Task
输出：完成或返工证据
→

5. 进入总账

按类型、状态、Plan、关联任务统一查询。

输入：各 Plan 的 Task
输出：全项目工单总览

Task 仍是唯一执行单元

id、subject、status、writable_paths、验证命令、成功判据、证据链和 route 都继续使用。

已确认

一个总账文件

.wildarrange/team/tasks.json 保存所有 Plan 的 Task、当前状态、关联关系和精简历史，不再只代表 active Plan。

Dashboard 直接读取这一份文件；现有 hash-chain ledger 只负责底层审计，不作为第二套用户工单。

新增字段

补齐工单语义

  • workType：feature / bug / acceptance_correction / maintenance
  • source：user / verifier / review / incident / imported
  • priority：P0 / P1 / P2
  • parentTaskRef：跨 Plan 关联原任务
  • request：原始诉求摘要与证据引用
新增状态

draft 先留底

创建时可以尚未知道验证命令；draft 不能 claim 或 run。执行前通过 task ready 校验范围、成功判据和非空验证命令。

这样既能“第一时间建单”，也不削弱现有质量门。

趋势与复盘

Bug 重开率、验收打回率、平均完成时长、重复失败规则等统计后做。

P0 先解决“有单、能找、能追溯”。

验收标准

  • 新功能、独立 Bug、已完成后的验收纠错都能先创建 Task draft，并获得稳定引用。
  • draft 缺少范围、成功判据或有效验证命令时不能进入 pending，更不能执行。
  • 任意执行、并行 Agent 与 admission 都能追溯到唯一 Task。
  • 总账能同时显示至少两个不同 Plan 的 Task；切换 active Plan 不丢历史。
  • 验收纠错能从新 Task 跳回原 Task；原 Task 的完成证据不被覆盖。
  • 同一 Task 内 verifier 失败只增加 attempt / evidence，不制造重复工单。
  • 现有 verifier → scope → review → acceptance proof → checkpoint 门禁全部保持。

方案原则：Task 是执行单元，也是工单；.wildarrange/team/tasks.json 是唯一工单总账；Plan 只是任务分组；ledger 只保留防篡改审计轨迹；Dashboard 是同一总账的可视化。
