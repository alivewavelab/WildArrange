WildArrange 档案路由员与关键词自进化方案

结论：路由不要只靠关键词，也不要每轮都让大模型做全量裁判。第一版采用“确定性关键词热路径 + ArchivistRouter 档案路由员”的混合结构；大模型固定使用 deepseek-v4-flash，只在新会话、Git 提交边界、低置信度、固定轮次触发，负责识别多意图、整理阶段档案、生成上下文注入包，并提出关键词库补丁。

一、为什么这样做

保留

关键词路由仍是主干

当前 src/helix-routing.mjs 已经能按 routes.json 做 intent/domain/complexity 路由，速度快、可解释、可测试，适合作为默认热路径。

补强

档案路由员处理语义和多意图

一句话里可能同时包含“继续、加功能、审核、发版”。关键词只能命中信号，ArchivistRouter 负责切段、排序、解释冲突、建议交给哪个 Agent，并生成下一轮应注入的阶段上下文。

演进

关键词库由档案路由员提出补丁

聊天阶段结束后，ArchivistRouter 从会话和执行结果中提炼用户习惯，只生成建议补丁；默认不自动改 routes.json，避免路由被一次误判污染。

二、外部证据

来源可借鉴点落到 WildArrange
OpenAI Agents SDK Handoffs handoff 是交给 LLM 选择的工具；支持目的地描述、结构化 metadata、input filter、会话历史压缩。 路由输出必须结构化；下游 Agent 不吃全量聊天，而吃过滤后的 routing packet。
LangGraph Workflows / Routing routing workflow 用 LLM 产出结构化决策，再走 conditional edges；orchestrator-worker 适合未知子任务。 先由 ArchivistRouter 产出 JSON，再决定是 answer、plan、execute、review、change_request 还是 release_git。
AutoGen SelectorGroupChat 模型基于共享上下文和 participant name/description 选择下一位 speaker，并保留上下文。 Agent prompt 的角色描述要成为路由输入的一部分，而不是散落在每个 Agent 自己判断。
LangGraph Memory 区分 thread-scoped short-term memory 与跨会话 long-term memory；长上下文会分散模型注意力。 保存会话摘要和用户偏好，不把完整无限聊天直接塞给路由模型。
vLLM Semantic Router 路由应组合关键词、语言、上下文长度、权限、神经分类、embedding 等多种信号。 WildArrange 第一版先做 keyword + LLM semantic；后续再加 embedding / feedback / cost routing。

三、角色定位

档案员

保存结构化阶段记忆

沉淀进展、结论、成果物、实现方式、调研来源、踩坑和未决问题。它不保存无限聊天全文，而保存压缩后的项目档案。

路由员

决定下一步交给谁

读取当前 prompt、确定性路由结果、项目档案和 Agent 描述，输出主路由、多意图片段、支持 Agent 和置信度。

维护员

迭代关键词和注入包

发现用户反复使用的表达，生成待审关键词补丁；同时生成下一轮注入给主 Agent 的 compact context。

五、触发规则

触发点原因默认动作
新会话 / SessionStart 用户可能删除或关闭旧会话，路由需要恢复阶段判断。 读取 resume/context/ledger tail 和结构化档案，生成本会话 routing context。
Git 提交后 / HEAD changed 提交是天然阶段边界，需求、代码状态和下一步工作会变化。 记录 commit hash、diff summary、已完成任务，刷新关键词建议。
按阶段轮数触发 长对话即使没有 commit，也会漂移；但不同阶段的信息密度不同。 计划/脑爆/澄清每 5 轮压缩；默认 10 轮；编码/验收/review 10-20 轮，当前配置默认 15 轮。
低置信度 / 冲突命中 例如“继续做并 review 一下新增功能”，关键词会同时命中 resume/execute/review。 立即启动 ArchivistRouter，按 segments 拆分主任务和附属任务。
workflow checkpoint / summary 一轮治理结束，最适合沉淀“这类任务以后怎么路由”。 生成 archivist route report，不自动改生产路由。

六、Routing Packet

ArchivistRouter 不吃完整无限聊天，而吃一个有上限、可审计的包：

  • 当前用户输入和确定性路由结果。
  • 最近 N 轮用户/助手/工具摘要：计划/脑爆/澄清默认 N=5，常规 N=10，编码/验收/review 默认 N=15，上限 N=20。
  • 采集模式为 conclusions-only：只保留用户意图、助手可见结论、工具结果摘要、执行证据摘要；默认剥离代码块、diff、完整命令输出和中间过程。
  • .helix/snapshots/context.json、.helix/ledger.jsonl tail、当前 task/workflow 状态。
  • 当前 routes.json、Agent name/description、可用 skills/tools 摘要。
  • Git HEAD、最近 commit message、改动路径摘要。
  • 已确认的用户偏好、团队规范摘要和长期结构化档案命中项。

七、结构化记忆

第一版不引入外部数据库或向量库。采用本地 structured files：JSONL 事件流 + JSON 摘要 + Markdown 人读摘要。十几万行级别先靠按阶段压缩、代码剥离和索引文件解决，后续再按需接 SQLite 或外挂记忆系统。

路径内容用途
.helix/memory/events.jsonl 阶段事件：prompt 摘要、路由决策、执行结果、验证结果、Git 边界。 可追溯事实源。
.helix/memory/stage-summaries/*.json 进展、结论、成果物、实现方式、调研、踩坑、未决问题；不保存完整代码。 跨会话恢复和上下文注入。
.helix/memory/index.json 关键词、领域、Agent、文件路径、成果物到摘要的索引。 长期记忆的关键词路由和快速召回。
.helix/routing/suggestions/*.json 关键词补丁、证据、风险等级、apply/reject 状态。 受控迭代 routes.json。

九、关键词演进门控

不能自动污染

默认只写建议

补丁写入 .helix/routing/suggestions/*.json 和 Markdown 摘要，不直接改 packs/wildarrange-linear/routes.json。

可选自动应用

高置信度才可自动合并

同时满足：confidence ≥ 0.85、同类证据出现 ≥ 2 次、没有覆盖 ask/review/release_git 等高风险规则。

高风险必须人审

Jiuwei / 用户确认

涉及验收、Git、权限、安全、删除、发布、计划外变更的关键词补丁，必须进入待审队列。

十、实现优先级

优先级模块验收标准
P0 src/helix-archivist-router.mjs 能构建 routing packet、判断触发点、调用 deepseek-v4-flash、写入 archive / route / contextInjection artifact；无 key 时不阻断主流程。
P0 src/helix-routing.mjs 确定性路由结果增加 confidence、conflicts、matchedGroups，供 ArchivistRouter 判断是否介入。
P0 src/helix-hooks.mjs SessionStart、UserPromptSubmit 能按规则触发 ArchivistRouter；不会每轮无脑调用 LLM。
P1 .helix/routing/suggestions 关键词补丁有证据、有来源、有风险等级、有 apply/reject 状态。
P1 CLI：route reflect / route suggestions 用户能查看、应用、拒绝关键词建议；所有动作写 ledger。

十一、判断

把档案员和任务路由放在一起是合适的。路由精准性依赖项目阶段记忆；阶段记忆的价值也体现在下一次能不能路由准确。第一版用 deepseek-v4-flash 足够，关键不是模型越贵越好，而是输入包结构化、剥离代码噪音、输出 schema 稳定、关键词补丁有门控。
