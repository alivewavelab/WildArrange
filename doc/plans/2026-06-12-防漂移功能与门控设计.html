防漂移功能与门控设计

目标：长会话里不让 Agent 凭聊天记忆乱改；每次改动必须落到任务单、范围、验收和 checkpoint。

P0：任务边界

  • 没有 active task 时禁止写业务文件。
  • 每个 task 必须有 writable_paths。
  • 计划外文件变更走 ChangeRequest。

P0：计划质量门

  • 高风险产品/体验类计划不能只拆 1-2 个任务。
  • 至少覆盖需求/设计、实现、验收、复核。
  • 缺少验收/复核任务时拒绝导入。

P1：验收强度

  • 测试不能只跑冒烟路径。
  • 新增功能必须声明不能破坏的旧行为。
  • review gate 对弱测试输出 testing gap。

P2：记忆恢复

  • 聊天结论沉淀到 digest。
  • 新会话从任务状态和摘要恢复。
  • 不依赖长聊天窗口做工程判断。

输入

用户需求、项目规则、上次 digest、Git 状态。

→

处理组件

route、plan import quality gate、PreToolUse scope guard、review/acceptance gate。

→

输出

可执行 task DAG、范围锁、验收证据、checkpoint 或 ChangeRequest。
