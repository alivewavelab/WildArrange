治理硬门PostToolUse 可跑 comment/lsp；start-work 有 review/debug gate 文本约束OpenCode hooks 更丰富自研 helix-gate，把 test/review/deploy 门做成工具返回值

三 · 借鉴而非照搬

借分层

按 Core / MCP / Skills / Adapter 分层。我们的 Core 是 vault/gate/compound 的纯逻辑；Codex/Claude/opencode 只做薄适配。

借 Stop hook

长任务不要靠模型记忆，用状态文件驱动续跑。.omo/boulder.json 的思路改成 .helix/work.json。

借证据账本

每个任务完成必须写 ledger，记录命令、产物、验证、cleanup。用于 review/test gate，也用于事后恢复。

借 Codex tool mapping

不要让 Codex 假装有 OpenCode 工具。所有子代理调用都显式用 multi_agent_v1.spawn_agent 的自包含 prompt。

借 review/debug gate

把 final review 与 runtime debugging 放成强制门，但用我们自己的小团队治理标准重写，不复制上游长 prompt。

不借角色神话

Sisyphus/Prometheus/Atlas 名字和 11-agent 全家桶对用户无感。我们保留“计划、执行、审查、调试”的能力，不保留复杂命名。
