WildArrange 产品总图改造

已实施并通过视觉验收 · 2026-08-24

唯一目标：让非研发读者一眼看懂“从哪里进入、系统怎样闭环、证据落在哪里”，不再把目录卡片和完整 import 图当作产品架构。
P0：全局职责
入口、任务闭环、可靠底座变成有留白的大区块；用箭头表达真实依赖，CLI 与 Interface 不再被误画成父子关系。
P0：三条作业
线性完成任务、并行成果合入、跨设备接力。每条都从用户动作画到 checkpoint / ledger。
P0：模块抽屉
每个模块只展示 3–6 个关键组件与关键跨区节点；禁止完整 import 扇出造成线团和裁切。

验收

  • npm run check:arch 保持 0 orphan、0 缺图。
  • 1440px、1024px、360px 截图中职责标题、卡片和箭头均不拥挤。
  • 打开 CLI、Orchestration、Capabilities 抽屉，关键链路可读且不超出画布。
  • 文件归属仍由 module-file-map.json 决定；产品流程由人工核实的 D 数据表达。
