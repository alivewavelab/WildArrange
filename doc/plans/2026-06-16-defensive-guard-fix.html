防御性兜底修复方案

目标：补上 Agent 误操作/篡改场景的防线，但不改变 WildArrange 已有线性工作流。正常 node、npm test、git diff、项目内 verifier 会继续运行；只有明显危险命令、config gate 被削弱、关键状态缺失时才给出阻断或明确告警。

修复卡片

P0

命令安全预检

在 shell 执行前扫描高风险命令，例如 rm -rf /、删除 .git/.helix、git reset --hard、git clean -fd、sudo、curl | sh。命中时返回 exit code 126，不进入 shell。

P1

Config 基线校验

新增 config baseline 和 config verify。基线记录 helix.config.json / .helix/config.json 的 hash，后续能检测 Agent 是否改弱质量门。

P1

运行态备份与缺失检查

新增 state backup 和 state verify。备份 ledger、work、tasks、config baseline；verify 在 resume 前可发现 ledger/tasks 缺失或断代。

P2

并行结果滞留可见化

保留当前 awaiting_user_acceptance 设计，不自动删除用户可能还要验收的结果；先通过 status/cleanup 命令和工具合同让滞留状态可见。

P1

基础模块职责收窄

把 ledger 追加与校验从 helix-foundation.mjs 拆到 helix-ledger.mjs，保留兼容导出。下一步再单独拆 helix-parallel-agents.mjs 的 admission 域。

P1

执行鲁棒性兜底

appendLedger 增加独立锁，避免并发写入 hash 链分叉；命令超时先 SIGTERM、再 SIGKILL；stdout/stderr 默认截断并保留 outputTruncated 元数据；node verify 失败回到 pending，方便下一轮 retry。

不影响边界

现有能力处理方式
线性 run / workflow不改状态机和 checkpoint 条件。
verify_commands正常命令继续执行；只拦明显破坏性命令。
Codex/Cursor adapter不改 hook 接入；只更新工具合同和 CLI 帮助。
已通过的测试新增覆盖命令拦截、config baseline、state backup/verify，不删除旧测试。

流程

输入
Agent 生成 plan、config 或本地状态变更。
→
防御组件
命令预检、config hash baseline、state backup/verify。
→
输出
危险命令被阻断；config 弱化可发现；关键状态缺失可告警。
