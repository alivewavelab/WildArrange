01 · 工作如何向下传递

五层职责关系

用户入口只负责接收和展示；任务流程层安排先后顺序；执行工具负责真正工作；底层保障负责文件、锁、Git 和日志。

命令入口bin/wildarrange.mjs接收终端或宿主命令，再转给真正负责的模块。
转交
用户入口层接入宿主并展示状态连接 Codex / Cursor / Kimi，提供看板、体检和操作入口。
发起
任务流程层决定先做什么、失败后去哪导入计划、选择任务、组织开发、检查、返工和成果合入。
参考
AI 判断层分类请求并准备工作材料给请求贴标签、匹配 Skill，并为 Agent 准备当前上下文。
调用
执行与质检工具编码、测试、范围检查和复核每项工具只完成一个清晰动作，并交回可核对的结果。
使用
底层运行保障文件、Git、锁、命令和日志保证上层可以安全、可恢复地读写和执行。
保存
本地运行记录.wildarrange/保存计划、工单、检查结果、完成记录、日志和备份。
工具调用：任务流程层和 AI 判断层只能通过统一入口调用编码、测试和复核工具。
什么时候算完成：Worker 说“做完了”不算完成；测试、范围、独立复核和验收证据都通过后才封口。
Hook 的作用：Hook 只是在关键事件发生时提醒或拦截，不是一直运行的工作循环。

04 · 程序从哪里启动

脚本和随产品发布的内容

这一段只回答四个问题：哪个文件接收命令、哪个文件跑测试、哪个文件维护架构图，以及安装包里还带了什么。

命令入口

无论用户还是宿主大模型调用，最后都从这里进入 WildArrange。

bin/wildarrange.mjs唯一公开命令为 wildarrange；负责参数解析和命令转交。
npm run wildarrange -- <args>package.json 对 CLI 的开发期快捷入口。

怎样运行测试

统一测试命令会逐个执行测试文件，避免 Windows 同时启动太多测试后互相卡住。

npm test调用 tooling/run-tests.mjs，执行 29 个 test/*.test.mjs。
wildarrange test --zone <zone>用依赖图选择分区或影响面测试。

怎样维护架构图

一个清单登记“每个文件属于哪个模块”，另一个程序检查是否有漏登记。

tooling/arch-module-graph/generate-module-graph.mjs从映射与代码事实生成模块图数据。
tooling/arch-module-graph/validate-module-file-map.mjsnpm run check:arch 的 owner，拦截无归属文件。
tooling/arch-module-graph/module-file-map.json当前登记 6 个物理根：CLI + 五区，unowned=[]。

安装包附带什么

除运行程序外，还会带上 Agent 说明、Skill、任务分类规则和项目初始化模板。

packs/wildarrange-linear/manifest.jsonPrompt Pack manifest；安装后按 realpath 与 hash 校验。
routes.json + tools/tool-contract.json确定性路由信号与 Tool 合同。
agents/ + skills/ + project-init/5 个长期 Agent 提示、29 个 Skill、项目初始化模板。
文件位置说明：仓库根目录没有单独的 scripts/ 文件夹。可执行程序实际放在 bin/ 和 tooling/，快捷命令登记在 package.json；图中按真实位置展示。
