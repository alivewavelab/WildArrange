P0

消除悬空 wisdom 文件

yinglong.md 曾要求派发前读取 learnings.md、decisions.md、issues.md，但 runtime 只写 verification.md。已改为读取 verification.md 和 .helix/memory/ 的 digest / archivist 索引。

P0

CONCEPTS 改为可选

CONCEPTS.md 当前不存在。已把 wa-recall / wa-compound 从“先读/顺手维护”改成“存在则使用，不存在不阻塞”，避免 Agent 第一步扑空。

P0

同步 Codex hard-after-trust 事实

已把 wildarrange-injection-runtime.md 改成分层表达：Codex 项目 hook 是 hard-after-trust；Cursor 是 soft；CLI 是手动 gate。Agent 不应低估 Codex hook，也不能高估 Cursor 规则。

P0

修正 wa-compound 存储路径

wa-compound.md 已统一到 .helix/memory/：短期写 digest/event，长期如需人为知识库再另设 export，不让 recall 和 compound 读写两套目录。

P0

更新 successCriteria 文案

yinglong.md 说 runtime 会为默认 criteria 自动记录 verifier evidence，这句话只对“未显式声明 criteria 的兼容默认项”成立。建议改成：显式 criteria 需要人工证据或 verifierCommandRefs。

P1

工具合同补新命令

tool-contract.json 应补 ledger verify、parallel cleanup、adapter install 写 .codex/hooks.json、dashboard POST token 约束。它是给 Agent 的工具地图，落后会让 Agent 选错路。

P1

减少跨产品旧话术

wa-run.md 已从“Claude 可加 model / Codex 用 spawn_agent”改为 WildArrange 自己的 parallel run --adapter、.helix/ 状态和 hard/soft adapter 分层语义。

P2

Agent 文案局部压缩

yinglong.md 286 行，是当前最长 Agent 提示词。它不是过长到危险，但可把 worker assignment 模板和 Final Verification Wave 拆成 Skill 或 reference，主 Agent 留硬边界。

建议修改流程

输入
  • 运行时新事实：Codex hard-after-trust、criteria 绑定、ledger verify、digest 注入。
  • 现有 prompt pack：agents、skills、tool-contract。
→
处理
  • 只改与运行时不一致的句子。
  • 保留角色边界和证据门。
  • 删除旧路径和跨产品口号。
→
输出
  • Agent 不再低估 Codex hard hook。
  • 记忆系统读写同一目录。
  • criteria 验收不再被误解为 verifier 回声。

不建议做

  • 不建议继续把外部 Agent prompt 的大段措辞缝进来；现在需要的是对齐运行时事实，不是堆更强语气。
  • 不建议把所有工具细节塞进 Agent 主提示词；工具合同和 skill 更适合承载可变命令。
  • 不建议把 Cursor 描述成 hard gate；目前它仍是 soft rule，必须诚实。
