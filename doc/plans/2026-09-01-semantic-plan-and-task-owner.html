语义识别生成计划，并让 task.owner 成为真实负责人

这不是新增一套计划系统，而是把已经存在的“路由、计划导入、用户批准、Agent 上下文”接成一条完整链。宿主大模型负责理解对话，WildArrange 负责限定格式、校验、批准和执行归属。

方向已由用户确认：进入实现

真实主流程

1. 用户对话用户描述需求、Bug 或其它开发目标。
2. 语义路由Hook 判断是否需要形成开发计划，并保留分类证据。
3. 宿主生成草稿宿主大模型按固定 schema 写入 .wildarrange/plan-drafts/。
4. WildArrange 校验检查任务、范围、测试、完成标准和每项 owner。
5. 用户确认语义生成计划一律等待用户批准，未批准不得 run。
6. 按 owner 执行Hook、Agent 上下文、任务领取和并行启动都读取同一个 task.owner。
7. 检查后完成测试、范围、独立复核和验收证明通过后才关闭工单。

保护机制

草稿只能写在专用目录尚无任务或计划待审批时，只放行 .wildarrange/plan-drafts/*.json；任意 Shell 默认拒绝，仅允许精确匹配的计划管理与只读命令。
生成计划必须标记来源宿主写入 generated_by: "host_semantic"，WildArrange 据此启用更严格校验。
每张可执行工单必须明确 owner语义生成任务的负责人只能是 command worker：Jiuwei 或 ZhuRong。只读 Agent 不得进入 worker。
强制人工批准即使项目全局关闭普通计划审批，语义生成的计划仍必须执行 wildarrange plan approve。
显式负责人优先计划里写明的 task.owner 不会被路由建议覆盖；路由决定只作为审计信息保存。
禁止身份漂移执行前 Hook 不再默认注入 Jiuwei；必须加载当前工单的真实 owner 和角色。

负责人从哪里来

场景真实负责人规则
宿主语义生成计划task.owner宿主按任务性质填写 Jiuwei 或 ZhuRong；缺失、只读 Agent 或未知值均拒绝导入。
人工编写计划task.owner显式值优先；保留旧计划默认值只为兼容现有手工计划。
任务领取与 Git 协调task.owner领取时可以显式变更，变更必须写入任务历史。
隔离子 Agent--agent 或 task.owner显式 CLI 覆盖用于一次隔离运行；否则读取工单负责人。
