WildArrange 治理最后一公里修复方案

一句话：先把“门真的独立、记忆真的被读、侧门真的加锁、对外承诺不夸大”四件事接通。不要一次重写框架，先修最影响治理可信度的断点。

生活类比：现在的大楼有闸机、值班室和登记簿，但部分闸机共用同一张通行条，值班室生成了日报却没贴到交接板，侧门只因为开在院内就默认不上锁。修复目标不是重盖大楼，而是让每一道已有设施真正承担不同职责。

证据判断

反馈点核验结论证据处理
successCriteria 被 verifier 自动翻绿 属实 src/helix-team.mjs 的 applyVerifierEvidenceToCriteria 会在 verifier pass 后把未通过 criteria 统一置为 pass；src/helix-node-runtime.mjs 调用后再 checkpoint。 P0 修复：默认 criteria 不再自动通过；只有带明确绑定的 criteria 才可由 verifier 证据通过。
digest / archivist 写了但 hook 注入没读 基本属实 src/helix-hooks.mjs 会计算 facts.digest 与 facts.archivist，但 appendHookFacts 只渲染 route/resume/continuation/scope/rules/agentContext。 P0 修复：把最近 digest 与 archivist 结果渲染进运行时注入块。
Codex/Cursor hook 没有真实硬接线 属实但需分层 src/helix-adapters.mjs 生成 .helix/adapters/codex/hooks.json 与 Cursor rule；项目文档也写了 Codex 深层插件安装仍是未来工作。 P0 文档降级承诺；P1 做真实宿主能力探测与安装路径，不把软规则宣传成硬拦截。
dashboard loopback 默认免 token，有本地 RCE 风险 风险成立 src/helix-dashboard.mjs 对 loopback 默认 requireAuth=false，但 /api/run-next 会触发真实 worker shell。 P0 修复：写操作强制 token 或一次性 session token；Host/Origin 校验；恒定时间 token 比较。
ledger 没有防篡改 属实 appendLedger 只是追加 JSONL；没有 prevHash/hash 链，也没有 verify 命令。 P1 修复：新增 hash chain 与 ledger verify，先做检测，不做加密签名。

修复卡片

P0

停止 successCriteria 自动复述 verifier

  • 移除“verifier pass 后所有 criteria pass”的默认行为。
  • 新增可选字段 evidenceSource 或 verifierCommandRefs，只有显式绑定的 criteria 才能由 verifier 自动通过。
  • 默认生成的 C001/C002/C003 必须保持 pending，除非计划导入时给出明确证据绑定。
  • checkpoint 继续要求 criteria 全部 pass，因此缺证据会真实阻断。
P0

打通 digest / archivist 读路

  • appendHookFacts 增加“记忆摘要”和“档案路由”两段。
  • 只注入短摘要：进展、决策、产物、风险、开放问题各最多 3 条，避免新上下文预算再次膨胀。
  • 当 digest 生成失败时注入 warning，不阻断主流程。
  • 把 wa-recall 的目录说明从 docs/solutions/ 修正到实际 .helix/memory/。
P0

dashboard 写操作加锁

  • GET /api/state 可继续本地免 token，降低查看成本。
  • 所有 POST 默认要求 token，即使绑定 127.0.0.1。
  • 增加 Host 白名单与 Origin/Sec-Fetch-Site 校验，阻断普通网页跨站触发。
  • token 比较改为 crypto.timingSafeEqual。
P0

对外承诺降级为真实状态

  • README / 架构文档明确：当前 Codex/Cursor adapter 是“上下文注入与规则提示”，不是所有宿主里的硬拦截。
  • adapter install 报告输出 enforcement level：hard、soft、manual。
  • CLI 输出下一步安装提示，避免用户误以为生成 JSON 就等于宿主已接入。
P1

ledger hash chain

  • appendLedger 每条事件写入 prevHash 与 hash。
  • 新增 node ./bin/helix.mjs ledger verify。
  • 不追求防 root 篡改，只先做到“改了能发现”。
P1

worktree 与 admission 后续治理

  • 新增 worktree cleanup 命令与生命周期状态。
  • admission 从“先合后验再回滚”改成“临时区验收通过后再合”。
  • patch 模式补充实际写入路径复核。

输入

输出

  • Agent 启动能看到最近记忆和路由
  • 本地 dashboard 不能被网页静默触发写操作
  • 文档承诺与实际强制力一致

验收标准

  • 新增测试：未手动记录或未显式绑定的 successCriteria，即使 verifier pass，checkpoint 也必须失败。
  • 新增测试：带显式 verifier 绑定的 criteria 可以自动通过，并记录具体命令证据。
  • 新增测试：SessionStart / PostCompact hook 输出包含“记忆摘要”和“档案路由”。
  • 新增测试：dashboard POST 在无 token 时返回 401；带合法 token 才能执行；跨 Origin 被拒绝。
  • 文档测试：README 与架构文档不再暗示 Codex/Cursor 已具备宿主级硬拦截。
  • 执行 npm test；涉及包内容变化后执行 npm pack --dry-run --cache /private/tmp/helix-npm-cache。

本轮不做

  • 不做完整加密签名账本。hash chain 只能发现普通篡改，不能对抗拥有本机写权限的人。
  • 不承诺立刻接入 Codex/Cursor 私有硬 hook。先把产品话术降级，避免空头承诺。
  • 不重写状态机。当前状态机主干是可用资产，问题在证据独立性和宿主接线。
