2. 本轮只关闭三组阻塞

阻塞 A：系统会给错危险建议

真实扫描已经把当前生效的根与分区 AGENTS.md、当前 Skill 建议为 archive；merge 也没有追踪旧脚本名的消费者。

完成标准：没有足够证据只能 defer，不能出现危险按钮。

阻塞 B：批准、执行和恢复不是一个原子过程

批准后真实文件变化检测不到；父目录 junction 可写出仓库；并发 start/apply/cancel、prepared 中断和 recovery_required 都可能落错状态。

完成标准：一次只有一个合法状态转换，出错后只有一个确定恢复动作。

阻塞 C：三文件和 Git 锚定不可信

Bootstrap/Inventory 生成后可能立即自判漂移；Runner 变化 doctor/status 看不到；commit A/B 只看同名路径存在，不看提交内容。

完成标准：生成后 fresh，改声明输入变黄，Git 中必须是同一份内容。

不在本轮：跨设备 adoption、穷举动态 Runtime Gate、自动 commit/merge/push、新 Agent、新账本、新测试框架、重构其他 dirty WIP、为未来语言预建插件框架。

4. 必须保留与必须移除

必须保留

  • 扫描阶段业务文件零写入、发现命令零执行。
  • Dashboard 是唯一写批准入口，一次批准和 Apply 一张卡。
  • 用户明确批准前不改目标；Git commit A/B 均由用户完成。
  • Registry、Bootstrap、Inventory 三文件分工。
  • 短 task lock + maintenance marker 的产品方向。
  • 既有 verify → scope → review → acceptance-proof → checkpoint 完成链。
  • 单一 verification-governance Skill；Hook 不静默扫描。
  • 旧 task archive API 对外字段和行为。

必须移除或改正

  • 仅凭文件名或 historical_archive 分类生成 archive。
  • 只因两个 script 命令相同就删除其中一个 script key。
  • 把 archive 默认放进 .wildarrange/。
  • 用卡片自身重算值冒充批准后的实时 stale 检查。
  • 目标不存在时跳过最近存在父目录 realpath 检查。
  • gateway 把 recovery_required 改成 capability_threw。
  • 只看 Git 路径存在就推进 commit A/B。
  • Dashboard 测试把 HTTP 500 当作可接受结果。

7. 允许保留的阻断条件

条件防止事故失败粒度
危险动作证据不完整 → defer误归档/误删现行文件或断开调用单卡
批准现场变化 → stale拿旧批准施工新内容单卡
路径/父 realpath 越界写出仓库单卡
活动 run/admission/adoption 互斥两套写流程互相覆盖会话
验证失败回滚；回滚失败 recovery_required半完成现场被当作安全单卡/会话
Git blob 或声明输入不一致三文件与真实仓库脱节会话

除上述条件外，新增阻断点数量必须为 0。不得新增授权层、账本、哈希门、恢复门、审批状态或全仓 Hook 扫描。

8. 最小测试与真实验收

先写能复现审查缺陷的最小测试

  1. 扫描 fixture 中生效的根/分区 AGENTS、当前 Skill：危险动作必须为零。
  2. 旧文档缺 successor 或仍有消费者：只能 defer；证据齐全才允许 archive。
  3. 重复 script key 仍被 CI/其他 script/Hook 引用：没有消费者迁移 patch 时只能 defer。
  4. 批准后修改真实目标或依赖 Runner：Apply 返回 stale 且业务树零写入。
  5. 不存在目标位于 junction/symlink 父目录：写入必须拒绝，仓库外零写入。
  6. 在 preimage、业务写、postimage、manifest 提交各断点中断：resume 保留最初 preimage 且幂等。
  7. 回滚失败：session、gateway、Dashboard/status 都是 recovery_required，marker 保留。
  8. 并发 start/apply/cancel 与普通 task lock：一个 session、一次 Apply、无提前释放。
  9. 生成 Bootstrap/Inventory 后立即 fresh；改 Runner 后 doctor/status 黄灯；无关文件变化不报警。
  10. 真实临时 Git 仓库完成 commit A/B：旧 blob、未提交工作树和同名旧文件均不能推进。
  11. Dashboard 非法 ID/超大 body 必须是精确 4xx，不允许用 500 作为 PASS。

人工七步 fixture

  1. 临时 Git 老项目记录初始 HEAD、状态和文件摘要；运行 start 后业务树不变。
  2. 确认生效 AGENTS/Skill、unknown 消费者没有危险动作。
  3. 批准一张 adopt、一张证据完整 archive；拒绝一张，暂缓一张；只改获批路径。
  4. 注入 Apply 失败与回滚失败，分别看到完整恢复和 recovery_required。
  5. 生成 Registry，由测试身份手工 commit A；确认提交 blob 与 session digest 相同。
  6. 生成 Bootstrap/Inventory 后立即 fresh；commit B 前改 Runner 必须变黄，恢复后才能 commit B/finalized。
  7. 改无关业务文件不报警；改 Registry/Runner/声明入口后 doctor/status 黄灯并给出下一步。
