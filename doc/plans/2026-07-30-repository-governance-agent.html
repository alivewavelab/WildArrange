检查清单与优先级

P0 · 阻断

文件归属与五区边界

文件是否落在声明的职责区；旧 shim 是否只做 re-export；新增能力是否经 gateway；非法反向依赖沿用现有边界测试。

P0 · 阻断

清单同步

Agent / Skill 的文件、manifest.json、routes.json、默认配置、tool contract 与测试是否同步。

P0 · 阻断

规则覆盖

被政策列为独立职责边界的目录必须有 AGENTS.md；路径、命令和引用必须存在，子规则不得削弱根规则。

P1 · 发布前阻断

README 与实际命令

中英文 README 核心章节和命令指纹一致；文档中的 CLI 命令可由 --help 或命令注册表证明存在。

P1 · 发布前阻断

架构目录台账

doc/project-architecture.md 中受治理的运行时模块与真实文件互相对账，发现过期路径和未登记的新模块。

P2 · 警告

命名与重复结构

目录/文件命名遵守声明规则和例外表；发现同义目录、大小写漂移、空目录、重复 README 或职责含混的“杂物间”。

“所有目录都有 AGENTS.md”不应按字面执行。只在独立职责、独立技术栈、高风险或高变更的边界设置；普通叶子目录继承最近父级规则，避免复制噪声。

机器级角色与增量审计边界

固定白名单

长期 Agent 集合必须严格等于 Jiuwei / DiJiang / ZhuRong / BaiZe / LuWu。Prompt manifest 额外允许唯一系统节点 Router；CangJie 只能出现在 ArchivistRouter/semantic shadow 配置，不能进入正式 Agent 清单或确定性路由结果。

执行权限

只有 Jiuwei、ZhuRong 可作为长期 Agent 进入 command worker。DiJiang、BaiZe、LuWu 属于只读长期角色；命令型临时子 Agent 仍可使用隔离运行目录，但不能借用这三个只读身份。

changed-only

--changed-only 只检查变更文件以及被变更触发的相关不变量：祖先 AGENTS、成对 README、Prompt Pack、命名、架构台账和注释。无相关变更时不得悄悄退化为全仓扫描。

CLI 事实

README 命令必须与真实 --help 输出对账，不能通过 CLI 源码里的注释、普通字符串或错误消息伪造“已实现”。关键安全标记也必须分别存在于中英文 README。

代码注释也纳入目录治理

复用现有 comment_check，但把检查从“全文关键词扫描”升级为“真实注释 + 路径规则”检查。通用交付中的注释质量门由 BaiZe 复核；LuWu 负责注释与仓库、目录规范之间的一致性，二者共用同一份确定性结果，不重复实现。

自然语言 AGENTS 用于给 Agent 解释上下文；会阻断发布的规则必须在机器可读 policy 中同步声明。否则只能提示，不能让 LLM 的主观解释直接决定 FAIL。

沿用当前静态装配机制

LuWu 不需要动态注册或运行时临时扩权。开发时一次性配置好角色 Prompt、模型、注入点、Tool 和 Skill，随版本发布；后续调整继续走代码 Review、测试和发布流程。

{
  "agents": {
    "LuWu": {
      "role": "repository_steward",
      "provider": "host",
      "model": "host-default",
      "reasoning": "high"
    }
  },
  "injectionPoints": {
    "repository_governance": {
      "tools": ["repository_governance_audit", "helix_rules_collect"],
      "skills": ["repository-governance", "init-deep"],
      "markdown": [".helix/reports/governance/latest.md", ".helix/rules/context.md"]
    }
  }
}

角色 Prompt 固定写入 agents/luwu.md 并登记到 prompt pack manifest；工具登记到 gateway / tool contract，再挂入 repository_governance 注入点；Skill 写入 prompt pack 并挂到同一注入点。初始化或刷新 prompt pack 后生效，运行期间不修改这些注册关系。

触发方式：快扫、全扫、发布扫

时机范围行为
日常实现完成后changed-only只扫描变更文件及祖先目录，目标是几秒内给出反馈。
手动治理fullwildarrange governance audit，生成完整结构报告。
发布前 / CIfull + docs + package复用 pre-publish-review，P0/P1 finding 阻断发布。
一键体检摘要doctor 展示最近一次治理结果，不执行修改。

一个必须顺手修掉的现有缺口

当前 src/infra/rule-scanner.mjs 只读取根级单文件和 .claude/rules、.cursor/rules、.github/instructions 等特殊目录；不会沿目标文件的祖先链发现普通子目录中的 AGENTS.md。

建议：对每个 target path，按“根 → 最近父目录”加载适用的 AGENTS.md，去重后再应用预算。否则现有的渐进式目录规范主要依赖宿主原生行为，WildArrange 自己的 review gate 并不能完整看到它们。

分阶段落地

Phase 1 · 可判定

政策、扫描器、CLI、测试

先实现确定性检查和 JSON/Markdown 报告；补齐嵌套 AGENTS 发现；不接自动修复，不立刻阻断普通开发。

Phase 2 · 可协作

LuWu + repository-governance Skill

按现有静态机制补全 Agent Prompt、manifest、routes、默认配置、Tool 与 Skill 注入点；Skill 保持短小，把详细规则表放到确定性配置和实现中。

Phase 3 · 可闭环

接入共享交付与 doctor

changed-only 先以 WARN 运行；修复任务仍经过 worker → verifier → review → checkpoint，LuWu 不自证完成。

Phase 4 · 稳定后门禁

发布 / CI 强制执行

用真实项目校准误报后，把稳定的 P0/P1 规则升级为发布阻断；命名偏好继续保持 WARN。

实施结果

Phase 1–3 与独立 Review 加固均已完成：5 个长期 Agent 由机器白名单锁定；LuWu 只读身份在 command worker 前被拒绝；CLI/README 使用真实 help 对账；模板表达式注释、changed-only 范围、Prompt/routes/架构台账和 doctor 摘要均已落地并有对抗测试。

Phase 4 保持显式控制：当前 governance audit 在 P0/P1 finding 时以退出码 2 失败，可直接接入 CI/发布脚本；不由普通开发命令静默开启新的外部发布动作。

验收标准

  1. 删除一个必需的子目录 AGENTS.md，审计稳定返回相同 finding ID 和证据路径。
  2. 新增 Agent 但遗漏 manifest 或 routes 时，发布审计 FAIL。
  3. README 写入不存在的 CLI 命令时，发布审计 FAIL。
  4. 把能力文件放错五区时，审计或现有 dependency boundary 测试 FAIL。
  5. 合法例外、继承父级规则的叶子目录不会产生误报。
  6. LuWu 只能提出修复任务；未经 verifier / review / checkpoint，不能标记治理完成。
  7. 以 LuWu、DiJiang 或 BaiZe 身份调用任意 command worker 时，必须在命令启动前拒绝且不产生工作区写入。
  8. 注册 Router + Rogue、把 CangJie 放入正式 routes 或遗漏固定 Agent 时，治理审计必须 FAIL。
  9. CLI 源文件里放置伪命令字符串，不能让 README 中的不存在命令通过审计。
  10. 模板字符串 ${...} 表达式中的真实 TODO/FIXME 注释必须触发注释门。
  11. npm test 与 npm pack --dry-run --cache /private/tmp/helix-npm-cache 均通过。

最终边界

Agent 管“理解与协调”，代码管“判定与证据”，现有流水线管“修改与放行”。

这样以后目录越多，规则也不会变成只能靠某个模型记住的隐性知识；同时不会为了追求形式整齐，在每个小目录里堆重复 README 和 AGENTS。
