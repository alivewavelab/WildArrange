WildArrange × Kimi Code 接入方案

日期：2026-07-28　状态：P0 + P1 已实施并通过质量门；P2 暂缓

结论：可以接，而且约 70% 已经天然兼容。 Kimi Code 原生读取项目 AGENTS.md 和 .agents/skills/； 现有 Helix 命令技能可以直接复用。真正要新增的是 Kimi Hook 插件、Hook 桥接器，以及可选的 Kimi 子 Agent 启动模板。

1. 生活类比

WildArrange 像一套工厂质检制度，Codex、Cursor、Kimi Code 是三个不同入口。 质检流水线本身不用重建；Kimi 已经认识工厂规章和操作手册，只缺一张能触发门禁检查的“Kimi 门禁卡”。 因此接入应只改入口适配层，不把 Kimi 专属逻辑塞进核心状态机。

2. 已核实的 Kimi Code 能力

能力官方事实对 WildArrange 的意义
项目规范 项目根目录 AGENTS.md 会作为项目指令加载。 现有 WildArrange 项目规范无需复制或转换。
项目 Skills Kimi 扫描项目 .kimi-code/skills/ 和 .agents/skills/；目录型 Skill 使用 SKILL.md。 现有为 Codex 生成的 .agents/skills/helix-*/SKILL.md 可被 Kimi 直接识别。
Hooks 支持 UserPromptSubmit、PreToolUse、PostToolUse、SessionStart、PostCompact、Stop、SubagentStop 等事件；输入是 stdin JSON。 事件名和 snake_case 输入字段与现有 hook run 基本一致。
阻断协议 PreToolUse 可用退出码 2，或 stdout 中的 hookSpecificOutput.permissionDecision = "deny" 阻断。 现有 WildArrange PreToolUse 输出协议可直接复用。
Plugins Kimi 插件可打包 Skills、Slash Commands、MCP 和 Hooks；本地插件由用户通过 /plugins install 安装。 用插件承载 Hook，比自动改用户全局 config.toml 更安全、可见、可卸载。
非交互运行 kimi -p 支持单次 prompt；--auto 可在非交互任务中自动处理工具许可。 后续可作为 WildArrange 命令型子 Agent 的 spawn adapter。

本机证据：/opt/homebrew/bin/kimi 当前为 0.27.0，其内置 Hook runner 已包含上述事件、stdin JSON 与 deny 输出协议。 当前官方文档展示的更新版本为 0.29.x；实施时以最新稳定版复测。

4. 分阶段实施

P0 必须

Kimi 项目 Adapter

  • CLI 增加 --target kimi，all 同时包含 Kimi。
  • 复用共享 .agents/skills/helix-* 生成器，不复制第二套命令正文。
  • 生成 .helix/adapters/kimi/plugin/。
  • 插件内只放 manifest 与轻量 Hook bridge。
  • 安装报告要求从项目根执行 /plugins install .helix/adapters/kimi/plugin 和 /reload。
P1 建议同批

完整 Hook 语义

  • UserPromptSubmit：注入规则、路由与待人决策。
  • PreToolUse：拦截越界的 Write / Edit / Bash。
  • PostToolUse：记录结果、匹配规范；不可阻断。
  • SessionStart / PostCompact：恢复状态；上下文在下一次 UserPromptSubmit 注入。
  • Stop：当主线仍需继续时，由桥接器转换为 Kimi deny，让 Agent 继续一轮。
P2 可选

Kimi 子 Agent Spawn

  • 新增 parallelAgents.spawnAdapters.kimi。
  • 支持 parallel run --adapter kimi。
  • 使用 kimi -p --auto 在隔离工作目录执行任务包。
  • 优先要求 git-worktree 隔离，再由现有 admission 合入。
  • 延长默认超时，不把 headless 输出当作完成证据。

5. 生成物与用户动作

node ./bin/helix.mjs adapter install --target kimi --mode local

# 从项目根启动 Kimi Code，执行（路径不要加引号）：
/plugins install .helix/adapters/kimi/plugin
/reload

# 验证：
/helix-doctor
/helix-status

adapter install 只在项目内生成文件，不自动修改 ~/.kimi-code/config.toml，也不替用户在 Kimi 中信任第三方插件。 adapter uninstall --target kimi 会备份并移除项目生成物，同时提示用户执行 /plugins remove wildarrange-adapter；全局插件卸载仍由用户确认。

6. 实际修改范围

位置修改分区理由

test/kimi-adapter.test.mjs（新增） 独立验证生成物和 Kimi Hook 契约，避免继续膨胀巨量测试文件。 对应单一 adapter 职责。

7. Kimi 与 Codex 的语义差异

Kimi Hook 是“可以阻断，但 Hook 自身失败时放行（fail-open）”。 因此不能把它宣传成绝对安全边界。PreToolUse 负责交互期尽早拦截； verifier、scope、review、acceptance proof、checkpoint 才是最终完成门。
事件Kimi 行为接入策略
UserPromptSubmit可注入上下文、可阻断直接复用 WildArrange Markdown 输出。
PreToolUse在权限确认前运行、可阻断直接复用现有 deny JSON。
PostToolUse仅观察记录证据，不能假装可以撤销已执行工具。
SessionStart / PostCompact仅观察，返回值不影响主流程执行恢复落盘；在下一次 UserPromptSubmit 注入上下文。
Stop可阻断并促使模型继续桥接器依据结构化 continuation 事实生成 Kimi deny。
Hook 超时/崩溃默认放行写诊断；最终交付门保持失败关闭。

8. 为什么不走另外两条路

不推荐：自动改全局 config.toml

用户配置可能已有模型、权限和其他 Hooks。自动合并 TOML 容易破坏注释与现有设置，卸载也难以精确恢复。插件管理器更透明。

不推荐：把 WildArrange 做成 MCP

MCP 适合提供“可调用工具”，不能天然截获 Kimi 内置 Write/Edit/Bash 的生命周期。WildArrange 的核心需求是治理 Hook，不是新增工具菜单。

不需要：ACP 作为项目接入层

ACP 用于 IDE 驱动 Kimi 会话。无论 Kimi 在终端、VS Code 还是其他 ACP IDE 中运行，项目治理仍应通过 AGENTS、Skills 和 Hooks 生效。

9. 测试与放行标准

  1. 安装目标测试：kimi、all、非法 target、重复安装、备份、卸载和恢复。
  2. 协议测试：用 Kimi 格式的 stdin JSON 覆盖 UserPromptSubmit、Edit allow、Edit deny、Bash、PostToolUse、Stop。
  3. 全局插件防串扰：非 WildArrange 项目必须立即 no-op，不得创建 .helix/。
  4. P0 + P1 失败对抗：非项目目录、伪造 marker、畸形 JSON、绝对路径越界、无扩展名路径越界、高危 Bash、PostToolUseFailure、Stop 续跑。
  5. P2 子 Agent 对抗（暂缓）：headless 退出 0 但无 patch、越界 patch、超时、结果文件伪造，均不得直接 completed。
  6. 运行 npm test。
  7. 运行 npm pack --dry-run --cache /private/tmp/helix-npm-cache，确认插件模板与新增模块进入发布包。
  8. 在已登录的 Kimi Code 最新稳定版做实机冒烟：技能可见、Prompt 注入、越界 Edit 被拒、合法 Edit 放行、卸载恢复。

10. 最终建议

P0 + P1 已完成，P2 子 Agent spawn 保持独立后续项。 当前版本已能在 Kimi Code 中读取规范、使用 Helix 命令、执行生命周期 Hook 和阻断越界写入； 同时未扩大 core、未改用户全局配置、未引入 MCP 服务器。自动测试 152/152 通过，npm 发布包预检通过。
