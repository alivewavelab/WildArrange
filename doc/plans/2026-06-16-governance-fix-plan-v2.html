WildArrange 治理修复方案 v2

一句话：先把"门真独立、宿主真接线、侧门真上锁、记忆真被读"四件事打通；其中 Codex 硬接入不是重写，是一次路径改正。不重写状态机，只修最伤治理可信度的断点。

落地调整（当时）：P0 已按 hard-after-trust 模型实现：Codex 写 .codex/hooks.json 并要求 /hooks trust。当时写的「Cursor 保持 soft」已过期，见页首：现为 hooks fail-closed（Write/Delete/Shell）。successCriteria 采用兼容迁移策略：显式声明的 criteria 不再被 verifier 批量翻绿，必须人工证据或 verifierCommandRefs；未声明 criteria 的旧任务仍生成 verifier-bound 默认项，同时对空 worker + 平凡 verify + 无 writable_paths 写 possible_noop_task warning。
生活类比：这栋大楼闸机是真闸机、协议也对，但门禁主机的线接到了隔壁空房间（写错路径），所以闸机一直没通电；同时五道闸共用同一张通行条（同一份 verifier 证据），值班室写了交接日报却没贴到墙上（记忆没被读），后院侧门因为"在院内"就默认不上锁（dashboard 本地免鉴权）。修复不是重盖楼，是把线接对、把通行条拆开、把日报贴上、把侧门加锁。

P0 — 让治理"真的成立"（本周）

P0 · 最高杠杆~30 行

Codex hook 接对路径 + 信任引导

schema 已对，只差落点与 Codex 的信任审批流。这是把"D 级假接入"一次性拉到"真硬拦截"的最省力改动。

  • 写入改为 <repo>/.codex/hooks.json（保留 .helix/adapters/codex/ 作为备份副本）。
  • install 后打印引导：在 Codex 内执行 /hooks review 并 trust（Codex 默认对非托管 hook 要求一次信任审批后才运行）。
  • uninstall 对称删除 .codex/hooks.json，并先备份。
  • install 报告输出 enforcement: hard（Codex）/ soft（Cursor）。
P0 · 治理核心~40 行

successCriteria 不再被 verifier 自动满足

否则"多维验收"是假的——verifier 一绿全绿。

  • 移除"verifier pass → 所有 criteria pass"的默认行为（helix-team.mjs:124）。
  • 新增字段 verifierCommandRefs：只有显式绑定到具体 verify 命令的 criterion 才能由证据自动通过。
  • 默认播种的 C001/C002/C003 保持 pending，缺证据则 checkpoint 真实阻断。
P0 · 安全~25 行

dashboard 写操作强制鉴权

挡住 DNS rebinding 借浏览器触发本机命令执行。

  • GET /api/state 保留 loopback 免 token；所有 POST 默认要求 token（即便 127.0.0.1）。
  • 加 Host 白名单 + Sec-Fetch-Site/Origin 校验，拒绝跨站。
  • token 比较改 crypto.timingSafeEqual。
P0 · 记忆闭环~35 行

打通 digest / archivist 读路

否则每次 SessionStart 跑的 LLM token 都在为没人读的产物买单。

  • appendHookFacts 增"记忆摘要"+"档案路由"两段，各最多 3 条（进展/决策/产物/风险/开放问题）。
  • 挂到 session_start / post_compact 注入点；生成失败注入 warning，不阻断。
  • 修正 wa-recall 目录指向 .helix/memory/。
