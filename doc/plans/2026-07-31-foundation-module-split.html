foundation.mjs 职责拆分评估

日期：2026-07-31。目标是降低基础设施耦合和误伤面，保持现有外部 API、配置语义、状态机、质量门与 Git 协调行为完全不变。

建议执行

结论

src/infra/foundation.mjs 应拆分。理由不是单纯超过 1000 行，而是同一文件存在至少六个独立变化原因：存储原语、Agent 注册表、配置、锁、快照上下文、Prompt Pack 与运行时初始化。

所有目标模块仍属于 infra；不新增跨区依赖，不放宽五区边界，不把任务完成决策放入 Infra。

现状证据

结构债务

1052 行，超过项目“1000 行默认拆分”的阈值。

高扇入

44 个 src 调用方直接 import foundation.mjs，形成事实上的内部总 barrel。

热点集中

nowIso 33 个调用方、appendLedger/resolveWildArrangePath 各 26 个、writeJsonAtomic 22 个。

独立演化

近期 Git 协调、Agent 治理、Kimi 适配和锁恢复都分别修改过该文件，证明变化原因并不单一。

实施顺序

  1. 先建约束：固化 41 项 Foundation 与 31 项 wildarrange-core 基线，新增导出集合回归；禁止五区实现继续 import infra/foundation.mjs，允许 legacy shim 继续兼容导出。
  2. 移动但不改行为：把原函数按上表迁入真实 owner，foundation.mjs 改成纯 re-export；先让现有调用方继续工作。
  3. 从底向上迁移 import：先 Infra，再 Capabilities，再 AI/Orchestration，最后 Interface；appendLedger 全部直连 ledger.mjs。
  4. 消除重复：ledger.mjs 改用 runtime-store 的时间、ID、路径与 hash 原语，保持 ledger 锁独立；Infra 成为 context 文件读取/渲染唯一 owner，AI 的同名 API 只做薄封装。
  5. 更新架构事实：同步根/Infra AGENTS.md、CLAUDE.md 与 project-architecture.md，不修改用户 README 行为说明。

放行标准

  • foundation.mjs 只含声明式 export，内部五区 import 数为 0。
  • 外部兼容面不变：Foundation/wildarrange-foundation 的 41 项导出集合完全相等，wildarrange-core 既有 31 项 Foundation 导出全部保留。
  • 无模块级循环、无新增跨区边，dependency boundary 全绿。
  • 锁并发/死进程恢复、配置 strict 恢复、两条 context 入口行为等价、快照自动刷新、Prompt Pack、ledger hash 链专项测试通过。
  • npm test、LuWu governance、npm pack --dry-run 全部通过。

风险判断

总体风险：中等。行为本身不复杂，主要风险来自 44 个调用方的 import 迁移、潜在循环和遗漏兼容导出。采用“先兼容 re-export、再逐层迁移、最后锁死边界”的顺序，可以把每一步保持为可运行状态。
