执行结果（2026-10-03）：第 1 节 6 条验收全部在真实 Claude Code 2.1.287 上通过：插件以 --user-root 隔离安装到沙盒配置（CLAUDE_CONFIG_DIR）；真实会话中计划外写入被拒、计划内写入成功、git clean -fdx 在 bypassPermissions 下仍被拦截、未完成任务停止时拉回一次；账本有 claude 宿主 5 类事件回执，doctor 显示 execution_observed；未连接目录不受影响；卸载后沙盒清空，真实 ~/.claude 与验证前一致。
实施中新增的设计（方案阶段未知）：① Claude Code 运行安装时的缓存副本、只按版本号刷新，故插件版本为 1.0.0-<内容摘要>，再次激活时版本不同即 claude plugin update，doctor 发现已装版本落后即告警；② Stop 输入 stop_hook_active=true 时放行（官方推荐，避免空转到 8 次上限）；③ claude CLI 在运行态目录执行，避免读到客户项目的项目级设置；④ marketplace remove 限定 --scope user；⑤ 宿主 fail-open 时 bridge 退出码固定为 1。
Kimi 交叉评审遗留（后续项）：两个项目使用不同 WildArrange 安装时会互相覆盖同名 marketplace；用户在 WildArrange 之外卸载插件后 doctor 仍显示已激活（与 Codex/Kimi 同属回执模型的局限）；Windows 上默认 claude 命令解析未验证，可先用 --claude-bin 指定。
结论：Claude Code 的钩子协议和 Codex 几乎相同（同样的 PreToolUse 拒绝格式、additionalContext 注入），插件结构和本地 marketplace 也与 Codex 同构，Stop 续跑可沿用 Kimi 逻辑。因此按「复制 Codex 插件包、换目录与变量名」实现，核心状态机不动。预计源码约 +150 行，另配测试与文档。
和 Kimi 同级的含义：插件外置在运行态、客户项目零写入；未连接项目静默放行；钩子 fail-open（崩溃或超时放行），最终完成仍以 CLI 质量门为准；doctor 以真实回执判定激活。

1. 验收标准（先定标准，再让实现通过）

#在已连接项目、真实 Claude Code 会话中证据

runtimeRoot/adapters/external/claude-marketplace/

  • plugins/wildarrange-governance/.claude-plugin/plugin.json

事件映射

  • PostToolUse → 规则刷新与结果门
  • Stop / SubagentStop → 未完成任务时 decision: "block" 续跑（同 Kimi）

代码改动

  • adapter-bundles.mjs：新增 writeClaudeBundle
  • adapter-bridge-template.mjs：host=claude，Stop 续跑分支
  • adapters.mjs：目标集合、activate / uninstall / 完整性检查
  • doctor.mjs、default-config.mjs（adapters.claude）、cli-help.mjs、bin 的 --target 说明

3. 需要你选：安装方式

选项做法评价
A（推荐）自动安装wildarrange adapter activate --target claude 代为执行 claude plugin validate → claude plugin marketplace add <包路径> → claude plugin install wildarrange-governance@wildarrange-local --scope user；卸载时执行 claude plugin uninstall 与 marketplace remove一条命令完成，和 Cursor 的 activate 一样是显式的用户级操作；Claude Code 官方提供这些命令行，适合脚本调用
B 手工安装像 Codex 一样只生成包，nextActions 列出上述命令让用户自己敲少一点代码，但多一步手工、容易漏

两种方式都以 user scope 安装，不写项目 .claude/settings.json，保持客户项目零写入。安装后需新开会话（或 /reload-plugins）才生效，doctor 以真实回执为准。
