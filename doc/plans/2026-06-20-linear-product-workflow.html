从设计需求到开发测试完成的线性治理流程

这是一条“用户提出设计需求 → 生成计划 → 执行开发 → 独立验证 → 测试完成”的线性路径。Agent 可以生产内容，但不能自己宣布完成；完成必须由 Gate 放行并写入证据。

阶段 / 注入 Gate / 限制 工具调用 失败返工

主流程

1. 用户提出设计需求

输入产品目标、设计想法、约束或验收期待。

注入内容
项目规则、AGENTS.md、历史 digest、路由上下文、可用 skill 摘要。
Gate / 限制
模糊需求不能直接执行；高风险或范围不清时降级到 plan / ask。
工具
hook run
archivist packet/run
skills match
↓

2. 需求理解与路由

判断是设计、实现、测试、修复，还是需要拆分。

注入内容
路由决策、主 Agent、支持 Agent、任务复杂度、推荐 skill。
Gate / 限制
低置信 execute 不直接开工；必须留下 deterministic 证据。
工具
node route --text
routeRequest
ArchivistRouter
↓

3. 计划生成 / 任务拆分

把设计需求转成可执行任务。

注入内容
任务目标、writable_paths、verify_commands、review_commands、successCriteria。
Gate / 限制
任务必须有独立 verifier；不得靠 worker 自证；高风险计划必须拆细。
工具
plan --from plan.json
task create
context build
↓

4. 设计 / 规格产出

产出设计说明、交互规格、验收场景。

注入内容
目标用户、核心流程、边界场景、验收标准、项目设计规则。
Gate / 限制
规格缺失不能进入编码；验收标准不能被后续 worker 私自改弱。
工具
context build --agent Jiuwei
prompts show
rules collect
↓

5. 开发执行

worker 按任务修改文件或生成产物。

注入内容
当前 task、允许路径、失败历史、相关项目规则、必要 skill。
Gate / 限制
PreToolUse 检查 active task 与目标路径；禁止越权写文件和危险命令。
工具
run
node execute
parallel run
hook run
↓

6. 独立验证

运行测试、类型检查、构建或专用验证命令。

注入内容
verify_commands、上一步 worker 证据、期望输出。
Gate / 限制
verify_commands 不能为空；exit code 不通过则任务回 pending / failed。
工具
node verify
npm test
npm run build
custom verifier
↓

7. 范围与质量复核

确认改动没有越界，质量门没有被绕过。

注入内容
git/file manifest、writable_paths、review lanes、项目规则上下文。
Gate / 限制
scope guard、review gate、LSP/AST/hashline/comment checker 可阻断。
工具
guard scope
node scope
node review
review_commands
↓

8. 验收证明 / Checkpoint

把完成条件汇总成可追溯 proof。

注入内容
worker evidence、verifier evidence、scope result、review result、successCriteria evidence。
Gate / 限制
所有条件硬 AND；任何一个缺失都不能 completed。
工具
node checkpoint
acceptance proof
ledger append
↓

9. 测试完成 / 可恢复交付

输出状态、摘要、可恢复上下文。

注入内容
完成摘要、失败记录、任务 digest、下一步 continuation。
Gate / 限制
ledger hash 链可校验；状态缺失可由 state verify 发现。
工具
status
summary
ledger verify
state backup/verify

失败返工路径

Gate 失败

不进入完成态，按失败类型回到对应环节。

注入内容
failure summary、retry hint、ChangeRequest、被拒路径、失败命令输出。
Gate / 限制
不能删除 verifier / successCriteria 制造 PASS；越界必须走 ChangeRequest。
工具
changes list/review/resolve
node retry
run

一句话版

Agent 负责生产

设计、编码、测试证据都可以由 Agent 产出，但只能作为 claim 或 evidence。

Gate 负责判定

verifier、scope、review、successCriteria、acceptance proof 全部通过，任务才算完成。

Ledger 负责追溯

每次通过、失败、返工、checkpoint 都入账，后续可恢复、可审计。
